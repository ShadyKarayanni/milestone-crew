# Preset: motion-graphics

For programmatic video and motion graphics: promos, showreels, explainers,
logo stings. Written for Remotion; the same plan fits any frame-driven tool
(for example HTML/CSS/JS captured frame by frame in headless Chrome, then
ffmpeg).

## Lessons: read before milestone 1

`motion-graphics-lessons.md` holds the paid-for gotchas (setup and licensing,
skills, storyboard, timeline and code, look, QA, rendering, sound, working
with the user, agent ops). Load it with this preset, before milestone 0 if
you run one, and always before milestone 1. Copy the lessons that apply into
the brief's "Gotchas already paid for". New lessons go there, not here.

## Kickoff questions

Ask these on top of the usual rounds. Skip any the user already answered.

- **Licence**: is this for a company of more than 3 people? Then Remotion
  needs a paid company licence. Buy it, or use the free route (HTML/CSS/JS,
  headless Chrome frame capture, ffmpeg)?
- **Format**: length, resolution, fps, aspect ratios (16:9, 9:16, 1:1),
  delivery file (MP4 H.264, ProRes, GIF).
- **Rhythm**: a music track with a known BPM, or a beat grid we pick
  (default 120 BPM at 30 fps = 15 frames per beat)?
- **Sound**: none, sound effects only, or music plus effects? Where do sounds
  come from (generated by our own code is safest) and who checks the licence?
- **Copy**: where does on-screen text come from? Verbatim from the product,
  or may we shorten it (labelled "shortened")?
- **Brand**: logo files (and a version that reads on dark), fonts, colours.
- **Skills**: which video skills to install, at project or user level, and
  may they be committed?
- **Previews**: stills and short clips as they are made, or only at milestone
  ends? Is the user watching remotely?
- **Machine**: may renders use every CPU core, or cap `--concurrency`?

## Default milestone plan

Defaults the kickoff proposes, not a fixed plan. The kickoff fits them to
the project and the user approves. Every "Done when" item must be observable.

0. **Install and review skills** (optional, ask first).
   Done when: the agreed skills are installed at the agreed level; a review
   subagent has read each one for scripts, network calls and broad triggers,
   and its findings are in the state file; conflicts with frame-driven
   animation are in the gotchas list; nothing is committed without the
   user's OK.
1. **Storyboard** (no code, in the state file).
   Done when: format, fps, BPM and frames per beat are written; the shot
   table covers frames 0..N-1 exactly, every cut on a beat multiple (a script
   parses the table and passes); each shot lists copy, main technique,
   transition and sound cue; copy is verbatim or labelled "shortened"; no two
   adjacent shots share a main technique; transitions are 6 frames or fewer;
   a legibility table shows no shot above ~3 words per second of hold;
   deliberate off-beat accents are labelled; the user approved it.
2. **Setup, style frames and technique test**: project scaffold, `brand.ts`
   (tokens, fonts, BEAT/BAR helpers, SHOTS table), 3 style frames (hook,
   product card, end card), and 2 or 3 short variant clips for each
   taste-heavy technique (e.g. a text morph).
   Done when: every `remotion` / `@remotion/*` package is pinned to one exact
   version in `package.json`; `out/` is gitignored; fonts are committed with
   their licence text; the 3 stills render and the user approved them; the
   variant clips render and the user's pick is in Decisions.
3. **Full silent animation**: parallel builders, one per scene file.
   Done when: the video stream has exactly N frames at the agreed size and
   fps (ffprobe); each cut lands on its storyboard frame (frame pairs at every
   boundary); a 1 fps contact sheet shows every shot with no blank or broken
   frame; on-screen copy matches the storyboard; a grep finds no CSS
   transitions, keyframes or animation libraries in scenes; every cross-scene
   handoff matches its contract; the user watched the full cut.
4. **Sound and final render**.
   Done when: every animated event on the cue list has a sound whose onset
   is within 1 frame of its frame (onset check on an SFX-only render);
   integrated loudness is −14 LUFS (±1) and true peak is −1 dBTP or lower
   (ebur128); impacts get louder toward the finale; `SOUNDS.md` lists every
   sound with source and licence; the final file has video and audio streams
   of the right length; a PSNR check against fresh stills shows the render is
   not stale; the user listened and approved.

## File ownership

- Split by scene file (`src/scenes/*.tsx`). One owner for `Promo.tsx` and
  `Root.tsx`.
- Every builder creates STUB scene files first, so the timeline compiles
  from the start.
- `brand.ts` is append-only. Builders add entries; nobody edits another's.
- Adjacent scenes with different owners get a handoff contract in the state
  file: the exact rect, colour and frame of the shape that carries the cut.
- Sound has one owner: synth script, cue list and master script.

## How QA verifies

- Length: ffprobe the VIDEO stream, not the container
  (`-select_streams v:0 -count_frames -show_entries stream=nb_read_frames,r_frame_rate,width,height`).
- Contact sheet: `ffmpeg -i out.mp4 -vf "fps=1,scale=480:-1,tile=6x5" -frames:v 1 sheet.png`.
- One frame: `ffmpeg -i out.mp4 -vf "select=eq(n\,N)" -vsync 0 -frames:v 1 fN.png`,
  or `npx remotion still <comp> fN.png --frame=N`.
- Cuts: extract frames N-1 and N at every known boundary and compare. Don't
  trust ffmpeg scene detection.
- Loudness: `ffmpeg -i final.mp4 -af ebur128=peak=true -f null -`, read
  Integrated and True peak.
- Sync: render SFX only, find onsets (`silencedetect` or an energy-onset
  script), compare each with its cue frame divided by fps.
- Stale render: PSNR between a frame of the final and a fresh still
  (`ffmpeg -i a.png -i b.png -lavfi psnr -f null -`).
- Storyboard: the shot-table script (coverage, beat multiples, adjacent
  techniques, words per second).
- Judge settled frames, not mid-animation ones. Taste calls go to the user
  with a clip, not a single still.

## Dev hooks to add

- A stills script: one settled frame per shot, frames read from SHOTS.
- The storyboard check script.
- An SFX-only render (a prop that mutes everything else).
- An audio-only path: render `--codec=wav`, run the master script (gain plus
  limiter), mux with `-c:v copy` onto the existing silent video.

## Ask first

- The licence decision, before choosing Remotion.
- Installing skills, `git add -f .claude/skills`, or changing `.gitignore`.
- `npx remotion upgrade` or any version change mid-project.
- Starting Remotion Studio or any server (check the port with `lsof` first).
- Third-party sounds or music, including anything streamed from
  remotion.media.
- Changing the logo (e.g. a white-filled copy of the wordmark).
- Full-concurrency renders while the user is working.

## Gotchas

See `motion-graphics-lessons.md`. The three that cost most:

1. A category word from the user ("metal sounds") is not a scope. Change
   exactly the timestamps they named.
2. Node writing to ffmpeg's stdin without draining stdout deadlocks. Use temp
   files and a `timeout` on every call.
3. `TransitionSeries` overlaps sequences and moves cuts off the beat grid.
   Use plain Sequences.

## Budgets

- Render time (reference): 900 frames at 1080p in ~85 s on Apple Silicon,
  all cores busy. Write the real number in the state file at milestone 2.
- Sound-only change: about a minute (audio-only render plus mux).
- Mix: −14 LUFS integrated, true peak ≤ −1 dBTP.
- Transitions ≤ 6 frames. Reading speed ≤ ~3 words per second.
